Upload demo

The acceptance bar, explained. shelf's upload path is validate → presign POST → upload → HEAD re-validate. This cockpit is read-mostly, so it does not fire a live upload from the browser (no creds, no bucket mutation) — instead it shows the exact command + the presigned-POST-over-PUT rationale, the way you'd run it from a terminal.

Run it from a terminal (the bar)
$ shelf upload ./avatar.png --bucket my-bucket --key users/42/avatar.png
  1. validate — magic-byte sniff + resource-consumption caps; refuses SVG-from-untrusted (the XSS vector). Never trust the client's Content-Type.
  2. presign POST — a POST policy (signs fields + conditions, and can enforce size/type) beats a presigned PUT, which silently ignores your size/type limit (P-01).
  3. upload — the browser/CLI POSTs the bytes straight to the bucket; the server never proxies the payload.
  4. HEAD re-validate — confirm the stored object's size/type matches what you signed; immutable key + DB pointer (so the CDN never serves a stale byte).

Want the URLs without uploading? The read-only mint lives in the CLI: shelf presign upload --bucket … --key … and shelf presign get --bucket … --key ….
